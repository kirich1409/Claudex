# CI/CD Quality Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up automated quality checks (build matrix, detekt, ktlint, Copilot AI review) that run on every PR and block merge until all pass.

**Architecture:** Five parallel GitHub Actions jobs (JVM test, Android compile, iOS compile, detekt, ktlint) run on every PR. A separate workflow triggers GitHub Copilot AI review. Branch protection enforces squash-only merges and requires all 5 CI jobs to pass.

**Tech Stack:** GitHub Actions, Gradle, detekt 1.23.7, ktlint (via `org.jlleitschuh.gradle.ktlint` 12.1.2), GitHub Copilot (repo-level plan).

## Task 3: Detekt configuration

**Files:**
- Create: `config/detekt/detekt.yml`

- [ ] **Step 1: Create the config directory**

```bash
mkdir -p config/detekt
```

- [ ] **Step 2: Create `config/detekt/detekt.yml`**

```yaml
build:
  maxIssues: 0

config:
  validation: true
  warningsAsErrors: true

style:
  MagicNumber:
    active: true
    ignoreNumbers:
      - '-1'
      - '0'
      - '1'
      - '2'
      - '4'
      - '8'
      - '16'
      - '24'
      - '32'
      - '48'
    ignorePropertyDeclaration: true
    ignoreCompanionObjectPropertyDeclaration: true
  MaxLineLength:
    active: true
    maxLineLength: 120
    excludeCommentStatements: true
  WildcardImport:
    active: true
    excludeImports:
      - 'kotlinx.coroutines.*'

complexity:
  LongMethod:
    active: true
    threshold: 40
  LongParameterList:
    active: true
    functionThreshold: 6
    constructorThreshold: 6
  TooManyFunctions:
    active: true
    thresholdInFiles: 20
    thresholdInClasses: 15

naming:
  FunctionNaming:
    active: true
    functionPattern: '[a-zA-Z][a-zA-Z0-9]*'
    excludes:
      - '**/ui/**'

exceptions:
  TooGenericExceptionCaught:
    active: true
  TooGenericExceptionThrown:
    active: true
```

Note: `FunctionNaming` uses a pattern that allows both `camelCase` (regular functions) and `PascalCase` (Composables) since Composable functions conventionally use PascalCase.

- [ ] **Step 3: Wire config path in root `build.gradle.kts`**

Add a detekt configuration block at the bottom of root `build.gradle.kts`:

```kotlin
detekt {
    config.setFrom(files("config/detekt/detekt.yml"))
    buildUponDefaultConfig = true
    allRules = false
}
```

Full root `build.gradle.kts` after this step:

```kotlin
plugins {
    alias(libs.plugins.androidApplication) apply false
    alias(libs.plugins.androidLibrary) apply false
    alias(libs.plugins.composeHotReload) apply false
    alias(libs.plugins.composeMultiplatform) apply false
    alias(libs.plugins.composeCompiler) apply false
    alias(libs.plugins.kotlinMultiplatform) apply false
    alias(libs.plugins.detekt)
    alias(libs.plugins.ktlint)
}

detekt {
    config.setFrom(files("config/detekt/detekt.yml"))
    buildUponDefaultConfig = true
    allRules = false
}
```

- [ ] **Step 4: Run detekt and fix any violations**

```bash
./gradlew detekt
```

If violations are reported, fix them. Common first-run issues:
- `WildcardImport` in generated files — add the file to detekt `excludes` patterns if needed
- `MagicNumber` in test files — add `ignoreAnnotated: ['Test']` under `MagicNumber` config

- [ ] **Step 5: Commit**

```bash
git add config/detekt/detekt.yml build.gradle.kts
git commit -m "build: add detekt configuration"
```

## Task 5: GitHub Actions CI workflow

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create the workflows directory**

```bash
mkdir -p .github/workflows
```

- [ ] **Step 2: Create `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  pull_request:
    branches: [ main ]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  check-jvm:
    name: JVM Tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - uses: gradle/actions/setup-gradle@v4
      - name: Run JVM tests
        run: ./gradlew :composeApp:jvmTest

  check-android:
    name: Android Compile
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - uses: gradle/actions/setup-gradle@v4
      - name: Compile Android target
        run: ./gradlew :composeApp:compileKotlinAndroid

  check-ios:
    name: iOS Compile
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - uses: gradle/actions/setup-gradle@v4
      - name: Compile iOS arm64 target
        run: ./gradlew :composeApp:compileKotlinIosArm64

  lint-detekt:
    name: Detekt
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - uses: gradle/actions/setup-gradle@v4
      - name: Run detekt
        run: ./gradlew detekt

  lint-ktlint:
    name: ktlint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - uses: gradle/actions/setup-gradle@v4
      - name: Run ktlint check
        run: ./gradlew ktlintCheck
```

- [ ] **Step 3: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add parallel CI workflow (JVM, Android, iOS, detekt, ktlint)"
```

## Task 6: GitHub Copilot review workflow

**Files:**
- Create: `.github/workflows/review.yml`

- [ ] **Step 1: Create `.github/workflows/review.yml`**

```yaml
name: Copilot Review

on:
  pull_request:
    branches: [ main ]
    types: [ opened, synchronize, reopened ]

permissions:
  pull-requests: write
  contents: read

jobs:
  copilot-review:
    name: AI Code Review
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Request Copilot review
        uses: github/copilot-code-review-action@v1
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
```

Note: `github/copilot-code-review-action` requires the repo to have GitHub Copilot enabled at the organization or repository level. If the action name changes, check the [GitHub Copilot documentation](https://docs.github.com/en/copilot/github-copilot-for-pull-requests) for the current action identifier.

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/review.yml
git commit -m "ci: add GitHub Copilot AI review workflow"
```

## Task 7: Branch protection (manual — GitHub UI)

This task is performed in the GitHub repository settings, not in code.

- [ ] **Step 1: Open branch protection settings**

Go to: `https://github.com/kirich1409/Claudex/settings/branches` → **Add rule** for branch `main`.

- [ ] **Step 2: Configure protection rules**

Enable the following:

| Setting | Value |
|---|---|
| Require a pull request before merging | ✅ enabled |
| Required approvals | 0 |
| Require status checks to pass before merging | ✅ enabled |
| Require branches to be up to date | ✅ enabled |
| Required status checks | `JVM Tests`, `Android Compile`, `iOS Compile`, `Detekt`, `ktlint` |
| Restrict pushes that create matching refs | ✅ enabled (blocks direct push to main) |

Note: Status check names must exactly match the `name:` field in each job in `ci.yml`. They only appear in the dropdown after the first CI run has completed.

- [ ] **Step 3: Configure merge settings**

Go to: `https://github.com/kirich1409/Claudex/settings` → **Pull Requests** section.

| Setting | Value |
|---|---|
| Allow merge commits | ❌ disabled |
| Allow squash merging | ✅ enabled |
| Default commit message | Pull request title and description |
| Allow rebase merging | ❌ disabled |

- [ ] **Step 4: Verify first CI run**

Push the CI/CD branch as a PR to `main`. Confirm all 5 jobs appear in the PR checks panel and pass.
